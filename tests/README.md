# Test boundaries

Unit fixtures validate file admission controls and the response schema. They are not predictions and are never included in the app. Browser tests run the production static export, including real ONNX inference when an artifact/demo image is present. Failure tests intentionally block model downloads to exercise the unavailable state. The Python test suite covers server decode/preprocessing/model loading/endpoints and real artifact loading separately. `python scripts/clinical_model_validate.py` executes the actual corrected photo checkpoint and ONNX demos, verifies CAM algebra, hashes, preprocessing, split groups, YES-valued body flags and the availability/history lock. Its real measurements demonstrate computation, not useful classification or fresh validation.

Routine unit tests cover strict preference validation, deterministic product matching, every combination of the supported ingredient exclusions, texture/sensitivity preferences, both purchasing priorities and reuse of owned basics. The standalone general-care builder accepts no model output. The separate condition-aware builder validates the exact clinical-photo task, rejects unavailable/uncertain/other and lesion outputs, independently recomputes score/margin requirements, and combines an eligible appearance category with survey constraints. Synthetic contract fixtures exercise these rules; the deployed photo model is unavailable and cannot activate them. The separate result-guidance unit tests validate routing for the exact seven-category dermoscopic task, every assessed label, unsorted scores, uncertain/unsupported/unavailable/quality-rejected states, malformed or contradictory responses, mismatched task/classes, and no all-clear language. These response fixtures are synthetic transport cases, not real predictions or accuracy measurements.

Price/selection unit tests validate the six dated HTTPS retail offers, integer cents, package provenance, selected-alternative totals, exclusion enforcement, existing-product reuse, missing-price refusal and nonmutation. Browser integration checks cover Quick guide keyboard/mobile behavior, survey-to-real-inference-to-automatically-displayed-product-combination navigation, preference edits without model execution, unsupported-image care boundaries, and deletion/refresh clearing preferences. The updated priced-option flow must retain ingredient exclusions when selecting an alternative, show the exact seller/package price, update the selected-combination item subtotal, and reset choices with preferences/session clearing. Products have manufacturer provenance plus dated public retailer prices; there is no live-price/stock feed, checkout or price/clinical optimization. The dated catalog is not a network mock for current availability, and arithmetic assertions do not verify future price freshness.

The standalone routine budget tests cover exact decimal-to-cent parsing, missing/invalid inputs, caps, tax and delivery, supported currencies, reused products and no-match refusal. Browser tests check that no image/model request or POST is needed, changes cannot retain prices for another product or currency, clear-session resets amounts and preferences, and the layout fits a mobile viewport. Entered prices in tests are explicitly synthetic arithmetic inputs, never claimed retail prices or live availability.

Run `npm run test:unit`, then `npx playwright install chromium` and `npm run test:e2e`. Additional browser tests verify the failed photo gate is visible before upload, no disabled weights or scores are returned, tampering with availability cannot bypass measured failure, and insufficient original resolution is rejected. Research-report tests preserve corrected counts, provenance and overlap disclosures. Browser tests build the export automatically; to reuse a freshly verified build, set `PLAYWRIGHT_SKIP_BUILD=1`. To target an already running frontend set `PLAYWRIGHT_BASE_URL` (tests will not start another server). Reports are in `playwright-report/`; traces/screenshots from failed tests are in `test-results/` and must not contain personal patient images.
