# Test boundaries

Unit fixtures validate file admission controls and the response schema. They are not predictions and are never included in the app. Browser tests run the production static export, including real ONNX inference when an artifact/demo image is present. Failure tests intentionally block model downloads to exercise the unavailable state. The Python test suite covers server decode/preprocessing/model loading/endpoints and real artifact loading separately.

Routine unit tests cover strict preference validation, deterministic product matching, every combination of the supported ingredient exclusions, texture/sensitivity preferences, both purchasing priorities and reuse of owned basics. Product matching accepts no image, model label or model score. The separate result-guidance unit tests validate routing for the exact seven-category dermoscopic task, every assessed label, unsorted scores, uncertain/unsupported/unavailable/quality-rejected states, malformed or contradictory responses, mismatched task/classes, and no all-clear language. These response fixtures are synthetic transport cases, not real predictions or accuracy measurements.

Price/selection unit tests validate the six dated HTTPS retail offers, integer cents, package provenance, selected-alternative totals, exclusion enforcement, existing-product reuse, missing-price refusal and nonmutation. Browser integration checks cover Quick guide keyboard/mobile behavior, survey-to-real-inference-to-automatically-displayed-product-combination navigation, preference edits without model execution, unsupported-image care boundaries, and deletion/refresh clearing preferences. The updated priced-option flow must retain ingredient exclusions when selecting an alternative, show the exact seller/package price, update the selected-combination item subtotal, and reset choices with preferences/session clearing. Products have manufacturer provenance plus dated public retailer prices; there is no live-price/stock feed, checkout or price/clinical optimization. The dated catalog is not a network mock for current availability, and arithmetic assertions do not verify future price freshness.

The standalone routine budget tests cover exact decimal-to-cent parsing, missing/invalid inputs, caps, tax and delivery, supported currencies, reused products and no-match refusal. Browser tests check that no image/model request or POST is needed, changes cannot retain prices for another product or currency, clear-session resets amounts and preferences, and the layout fits a mobile viewport. Entered prices in tests are explicitly synthetic arithmetic inputs, never claimed retail prices or live availability.

Run `npm run test:unit`, then `npx playwright install chromium` and `npm run test:e2e`. Browser tests build the export automatically; to reuse a freshly verified build, set `PLAYWRIGHT_SKIP_BUILD=1`. To target an already running frontend set `PLAYWRIGHT_BASE_URL` (tests will not start another server). Reports are in `playwright-report/`; traces/screenshots from failed tests are in `test-results/` and must not contain personal patient images.
