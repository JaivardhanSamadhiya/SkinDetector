# Data processing and security boundaries

## Default browser inference

The default build loads local ONNX models and matching WebAssembly from the same website origin. Images are decoded/processed in the browser; no image-analysis request goes to a third-party model service. `clinical_photo` stays on-device even if the optional backend is configured for dermoscopy. Historical MobileNet inference remains unavailable. Photo-v2's genuine reference model has been evaluated; its repaired split-file float32 graph has passed actual ONNX remeasurement and Chromium WASM parity; release activation validates that immutable evidence. V2 research outputs stay uncertain and cannot drive condition-specific products, because measured accepted accuracy was only 47.73%. Browser memory holds the file, preview and result until cleared/page closure. The app collects no names, contact details, payments or health histories and has no image-history database.

Use the result removal control to clear the selected image/result and release preview object URLs. Reloading or closing the page also ends the in-memory session. Browser/app behavior cannot remove a user's original camera/photo-library file, browser crash dumps or operating-system caches. Do not describe local processing as a guarantee that every device leaves no traces.

Static hosting providers receive ordinary site/model-download requests and may log IP addresses and request metadata. Configure their retention and analytics policy before a public deployment. Do not add analytics that capture image content, filenames or results.

The private Sites demo also uses the hosting provider's bot-detection challenge, which makes its own security requests. These are separate from image inference; the hosted application still runs its model in the browser. The demo's private hosting gate requires the owner's existing account even though the application itself has no account or image-history system.

## Session-only routine preferences

The seven-item survey records self-reported skin feel, sensitivity, purchasing priority, numeric new-product USD cap, texture, three ingredient exclusions and owned basics. Answers/product IDs stay in React memory, never local storage, URLs, analytics, a database, model tensors or multipart requests. Analysis requires Save or explicit Skip; editing requires saving again. **Skip records general defaults, including a $50 cap**, rather than deleting the session. Replacing an image preserves answers/choices; deleting the image/result, Clear session, refresh or page closure clears them. Editing answers resets the filtered starting basket. No allergy history or comprehensive allergen screening is provided.

Product links open manufacturer/retailer sites with their own data practices. SkinSnap transmits no answers, image content, results or selections to those sites and has no affiliate relationships, checkout, purchase tracking or conversion analytics. Future correctly versioned accepted appearance rules are local; v2 explicitly blocks them, including for manipulated accepted payloads. Research labels are not diagnoses and rules lack product-response validation. Ingredient exclusions and reuse remain mandatory. Uncertain/other/unsupported/unavailable/malformed results cannot activate condition matching; dermoscopic labels supply professional-assessment education only. Check the full current package because formulations/availability can differ.

The application includes six manually checked US retail snapshots/links/package sizes dated 12 October 2026, not live retailer requests or checkout quotes. The numeric cap enumerates complete eligible baskets using integer-cent prices, prefers the best ordinal-rank combination within the cap, and otherwise shows the cheapest complete basket and shortfall. Owned steps add zero new spending; missing items/prices prevent a complete affordability claim. User-selected alternatives update cap feedback. Subtotals exclude tax/delivery and establish neither current availability nor suitability for a photographed finding.

The standalone `/routine/` workflow works without an image or model execution. Alongside dated product prices, its separate budget checker uses amounts entered by the user, including tax and delivery; it has no live retailer price/stock feed and makes no purchase or savings claim. Amounts remain in local component memory, never in URLs, storage or network requests. Currency or selected/reused product changes reset the entered amounts rather than converting them or keeping another item's quote, and the page's clear-session control clears preferences, product choices, entered prices and any previously selected image/result. A future merchant integration or aggregate experiment would require its own explicit data-processing review; none is active in this prototype.

## Optional FastAPI mode

Setting `NEXT_PUBLIC_INFERENCE_URL` changes the image-processing location for the original dermoscopic task. The app sends that selected image as multipart data to the configured service over HTTPS. The separate clinical-photo route bypasses this service and stays on-device; this backend does not load the new photo model. Inform users of the actual processing host and mode before they upload. The backend validates MIME/content, byte length, decoded dimensions and animation, applies orientation, decodes to RGB, performs in-memory inference, and returns scores/quality plus an explanation when available. It does not create a permanent image store.

Application logs must not include image bytes, filenames, multipart request bodies, EXIF or model results. Reverse proxies, monitoring platforms and the host may independently buffer/log requests. Disable request-body capture and error-report attachments, configure short retention, and verify the deployed settings. Multipart parsing may use framework-managed memory buffers or operating-system temporary spool files; the application closes these on success, rejection, cancellation and errors. This is not a guarantee of forensic erasure from a host's storage. No retained-image deletion endpoint is necessary while no image store exists. If storage is added later, provide authenticated deletion, retention limits and user consent before collecting data.

## Upload admission controls

Only single-frame JPEG, PNG and WebP images are supported. The selected file is size-limited and must decode as an image before analysis. The optional server revalidates every upload rather than trusting client checks or filenames. Uploaded files are never executed, imported, served as HTML or written as executable content. Supported-domain selection is a user assertion; it is not a validated automatic dermoscopy or skin-photo domain detector. The photo model's heterogeneous other class does not establish arbitrary-image rejection. Images outside the declared supported use case receive an unable-to-assess state.

Quality checks are heuristic warnings/rejections for resolution, focus and exposure. They do not certify medical suitability. Model scores are not disease probabilities. Uncertainty thresholds are research heuristics, and a low score does not exclude illness. The educational safety message remains visible even when the model selects a label.

## Research data and demonstrations

Training uses public source data, never uploads or survey answers. Original downloads/caches stay in ignored `data/clinical/`, `data/photo-v2/` and `data/fitzpatrick17k/`. Demo images have explicit attribution, resizing/metadata-removal records and source URLs; old SCIN examples are development examples, not independent v2 test evidence. SCIN prohibits re-identification; anonymous case keys are not patient accounts and lack of patient IDs prevents patient-independence claims. Do not identify/contact/link contributors. Dermoscopic images retain CC BY-NC 4.0; original Fitzpatrick17k atlas photographs retain research CC BY-NC-SA 3.0/source attribution. Corrected metadata does not relicense images; DINOv2's separate Apache license does not clear downstream rights or clinical/paid deployment.

## Deployment controls

Keep secrets in the deployment environment; `.env.example` contains placeholders only. `NEXT_PUBLIC_*` values are public and embedded into the browser bundle. Use HTTPS, origin-restricted CORS for the optional API, bounded payloads, rate/concurrency limits, timeouts and operational monitoring. Do not expose Python debug tracebacks publicly. Never load untrusted serialized model artifacts; use the documented artifact source and checksums.

The included configurations are for nonclinical demos. No authentication, patient record system, consent-management service, clinical audit trail, penetration test or regulatory certification is claimed. Review these needs for any intended expansion and assess actual deployment behavior before making privacy promises.
